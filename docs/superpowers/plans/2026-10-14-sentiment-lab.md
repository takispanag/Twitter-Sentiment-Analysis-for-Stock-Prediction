# Sentiment Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver reproducible sentiment research, an interactive dashboard, and an execution-aware simulator/forward paper ledger on a dedicated branch.

**Architecture:** One local Python package owns canonical session features and forecast artifacts. CLI runs produce CSV/JSON artifacts; Streamlit and the simulator consume the same forecasts. SQLite holds append-only forward paper records.

**Tech Stack:** Python 3.11+, pandas/numpy/scikit-learn, vaderSentiment, pandas-market-calendars, Plotly/Streamlit, optional XGBoost/PyTorch/transformers, pytest, standard-library SQLite.

**Spec:** `docs/superpowers/specs/2026-10-14-sentiment-lab-design.md`

## Global Constraints

- All source changes stay on `feature/sentiment-research-dashboard-paper-trading`.
- Full timestamps are timezone-aware UTC; date-only posts are unavailable until the end of their entire UTC day.
- Forecasts use only data available by their cutoff. Training cutoff is the latest training target close, strictly before forecast issue time.
- Primary target is next-session open-to-close simple return; `next_close` and volatility experiments are explicitly separate.
- Date-aligned ablations use the same held-out observations, train-only transforms, and deterministic seeds.
- Synthetic demos and recovered date-only non-neutral historical subsets are clearly labelled. Never commit the recovered corpus or secrets.
- Dashboard and simulator consume the same persisted forecast schema. No automatic network calls on dashboard load.
- Forward recording accepts no actuals, requires issue time <= record clock < target open, is idempotent for identical rows, and refuses changes to recorded identities.
- Implementers write tests first, run red then green, own only their task files, never spawn subagents, and never commit/push. The coordinator commits after verification/review.

## Task 2: causal features, walk-forward research, and legacy repair

**Files:** create `sentiment_stock/features.py`, `sentiment_stock/research.py`, `sentiment_stock/sequence.py`, `tests/test_features.py`, `tests/test_research.py`, `tests/test_legacy.py`; modify `sentiment_stock/cli.py`, `main.py`, `linear_pipeline.py`, `lstm/lstm_model.py`, `lstm/lstm_trainer.py`, `lstm/lstm_pipeline.py`, `sentiment_analysis.py`, `get_tweets.py`, `stock_prices_acquisition.py`, `utils.py` only as needed.

**Interfaces:**
- `build_features(prices: pd.DataFrame, posts: pd.DataFrame, target: str='return', events: pd.DataFrame | None=None) -> pd.DataFrame`: canonical inputs from Task 1. Per ticker compute causal close return and trailing volatility/momentum/volume features; sentiment mean/std, pos/neutral/neg fractions, log count, unique authors, missing flag, sentiment change/trailing mean. Aggregate posts by availability into `(previous session close, current session close]`; preserve weekends naturally. No-post days stay present. Issue time=`market_close+15min`; input cutoff=`market_close`; target_kind return/next_close/volatility, next session date/open/close and next open/close prices, actual return. Target rows with missing price sessions must not jump over the missing NYSE session silently.
- `sequence_windows(features: np.ndarray, lookback: int) -> tuple[np.ndarray,np.ndarray]`: chronological windows and end-row offsets; output [examples, lookback, features], reject insufficient/nonfinite data; caller handles labels at matching offsets. Use for both modern and legacy LSTM flows.
- `run_research(features: pd.DataFrame, output: Path, *, seed: int=11, n_splits: int=3, include_models: bool=False, dataset_metadata: dict | None=None) -> dict`: naive constant return/persistence close baseline; linear/LinearSVR and optional XGBoost/LSTM; feature_set names `price_only`, `attention_only`, `price_attention`, `price_sentiment`, `shuffled_sentiment`; constant baseline uses feature_set `naive`. Define cols in exported metadata. Paired comparisons include naive error and same-family price_attention error to isolate sentiment beyond attention. Ticker-local chronological folds with target-close eligibility filter. Include comparable validation and test results in distinct columns/splits, or only honest walk-forward test folds if no tuning occurs. Fit all transforms/train models only on fold train rows. Optional neural early stopping uses a chronological subset of train rows. Keep held-out common dates after lookback warmup. Seed all models; cap neural epochs for runnable demo.
- Persist `features.csv`, `forecasts.csv`, `metrics.csv`, `regime_metrics.csv`, `comparison.csv`, `posts_sample.csv`, `metadata.json`, plus fitted latest models/scalers for the CLI forecast path. `forecasts.csv` columns: `run_id,ticker,feature_date,issued_at,input_cutoff,training_cutoff,target_date,target_open_at,target_close_at,target_open,target_close,target_kind,model,feature_set,fold,prediction,actual,actual_return,volatility_regime,dataset_type`. Forecast IDs can be derived from run_id/ticker/issued_at/model/feature_set/target_kind; metadata includes encoder/provenance. `comparison.csv` has paired baseline MAE improvement and time-block bootstrap interval, seed and block length; classify statistical evidence cautiously.
- `forecast_latest(prices: pd.DataFrame, posts: pd.DataFrame, output: Path, *, as_of: pd.Timestamp, model: str='linear', feature_set: str='price_sentiment', seed: int=11) -> pd.DataFrame`: fit only resolved historical targets through as_of; build latest fully closed session features; get next NYSE session from calendar, not fabricated OHLC. Return only forward records without target prices/actuals. Issued_at=input cutoff+15m must be <= as_of; reject after next open. Support provided/VADER scores; save metadata/model provenance and forecast.csv. This enables real forward paper recording without historical actual leakage.
- Extend CLI: `run --prices PATH --posts PATH --output PATH --target {return,next_close,volatility} --encoder {provided,vader,finbert,twitter} --include-models --splits N --seed N --events PATH`; `demo --output PATH --include-models`; `forecast --prices PATH --posts PATH --output PATH --as-of ISO`.
- Legacy repair: direct y/prediction matching; chronological train/val splitting; LSTM keyword batch_first and linear output; identical lookback at inference; clear insufficient-data failures, train-only scalers, no minimum-epoch checkpoint bug; use recursive directories. Legacy live collector calls scorer with the newly collected rows and passes its returned df to sentiment_avg; consistent output locations. Prefer compatibility parameters rather than duplicate logic. Guard private config imports or provide useful setup errors.

## Task 3: simulator and persistent forward paper ledger

**Files:** create `sentiment_stock/trading.py`, `sentiment_stock/paper.py`, `tests/test_trading.py`, `tests/test_paper.py`; extend `sentiment_stock/cli.py`.

**Interfaces:**
- `backtest(forecasts: pd.DataFrame, *, model: str='linear', feature_set: str='price_sentiment', threshold: float=0.0, cost_bps: float=5.0, slippage_bps: float=5.0, initial_cash: float=10000.0) -> tuple[pd.DataFrame,pd.DataFrame,dict]`: reject unsupported target kinds, duplicate ticker/session forecasts, malformed/nonfinite timestamps/prices, issue after entry, or training after issue. One strategy per ticker; capital divided equally across selected tickers, missing forecast session stays cash; deterministic session ledger. Enter long if predicted return > threshold, exit target close. All available predictions are used once; no target-based threshold tuning. Buy-and-hold benchmark holds equal allocations from first eligible open through each subsequent close including overnight moves, with entry cost; clearly document final liquidation treatment. Compute metrics on complete aligned daily equity. Include gross/net equity, return, benchmark equity, drawdown, exposure and traded notional. Cost is charged per side; slippage affects entry/exit fills.
- `cost_sensitivity(forecasts: pd.DataFrame, **strategy) -> pd.DataFrame`: evaluate 0,5,10,25 bps per-side fees with slippage explicit; return labelled results.
- `record_forecasts(db: Path, forecasts: pd.DataFrame, *, recorded_at: pd.Timestamp | None=None, threshold: float=0.0, cost_bps: float=5.0, slippage_bps: float=5.0) -> int`: transaction validates entire batch before any write; only fields without actual/target prices; issue<=clock<target_open; training_cutoff<issue; input_cutoff<=issue; unique identity includes run/model/features/ticker/target; idempotent exact repeats, reject changed repeats. Store input record JSON, timestamps and immutable strategy parameters in SQLite, no overwrite.
- `settle_forecasts(db: Path, prices: pd.DataFrame, *, as_of: pd.Timestamp | None=None, threshold: float=0.0, cost_bps: float=5.0, slippage_bps: float=5.0) -> int`: prices canonical Task1, only settle after target close; store immutable execution results. A strategy choice is fixed at recording time or ledger creation, not after observing return. Transactions and idempotent repeated settlement; reject mismatched session prices and invalid fees. No historical-batch insertion into forward ledger. Distinguish forecasts with same ticker/session but different experiment strategies to avoid double-counted portfolios.
- `read_paper(db: Path) -> pd.DataFrame`: pending/settled records suitable for dashboard; missing database yields empty, inspection must not create DB. Include recording clock and all provenance.
- CLI: `backtest --run PATH --output PATH --model NAME --feature-set NAME --threshold FLOAT --cost-bps FLOAT --slippage-bps FLOAT`; `paper-record --forecasts PATH --db PATH --threshold FLOAT --cost-bps FLOAT --slippage-bps FLOAT`; `paper-settle --prices PATH --db PATH`; `paper-status --db PATH`. Record uses actual current clock, no user-provided fake clock in production CLI; tests inject clocks through functions only. Export equity.csv/trades.csv/summary.json/cost_sensitivity.csv.

- [ ] **Step 1: Write red tests for accounting and temporal validation.** For cash1000 and no costs, predicted+.1/open100/close110 ends1100; predicted-.1 stays1000. With fee10bps per side, use hand-derived entry/exit fee arithmetic. Zero signal should remain cash. Issue after target open and close-price targets must fail. Two tickers with opposite gains average according to allocations, not sum full-capital profits. Buy-and-hold includes overnight return across two sessions.
- [ ] **Step 2: Implement simulator and cost sensitivity.** Never use realized return for position choice. Reject negative/nonfinite cash/costs/thresholds. Keep table rows traceable to forecast identity and actual fill prices.
- [ ] **Step 3: Write red tests for paper ledger.** A row issued yesterday for tomorrow's open records at today clock. Identical retry returns0, modified prediction fails, past target fails, a row containing actuals fails. Recording two rows with one invalid row leaves zero new entries. Settlement before close remains pending; after close settles once. Reopening SQLite retains records; changing threshold after recording must not change execution decision.
- [ ] **Step 4: Implement atomic SQLite persistence and CLI.** Store strategy parameters before actual outcomes. Do not delete or replace records. Reject attempts to settle a different ticker/date or rewrite settled prices. Track statuses separately from historical backtest outputs.
- [ ] **Step 5: Run tests and demo backtest CLI; document commands/results in report.** Forward ledger tests use deterministic clock injection, while production uses wall clock. Do not populate forward demo ledger using historical forecasts.
