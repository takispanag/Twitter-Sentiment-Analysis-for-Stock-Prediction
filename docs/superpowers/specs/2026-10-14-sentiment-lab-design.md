# Sentiment Lab: research, dashboard, and paper trading

Approved scope: revive the existing Python project on `feature/sentiment-research-dashboard-paper-trading`, combining trustworthy research, an interactive Streamlit portfolio, and trading research/paper records. Preserve the old project and correct its material forecasting bugs. No deployment or live broker integration is required.

## Shared rules

- Python 3.11 or newer; package `sentiment_stock`; local-first CLI and Streamlit. Core dependencies: numpy, pandas, scikit-learn, Plotly, Streamlit, vaderSentiment, pandas-market-calendars, yfinance. XGBoost/PyTorch and transformers are optional extras. Pytest is the test extra.
- Use NYSE trading sessions with UTC market-open/close timestamps, including holidays and early closes. Reject malformed/nonfinite/duplicate market rows; sort before all time-dependent operations.
- Full-timestamp posts use timezone-aware UTC. Date-only historical posts become available only after their entire UTC day has ended. Mark that conservative assumption. Retain post IDs/text/tickers/source, optional authors and observed-at timestamps. Use the later of created-at and observed-at to determine availability. Deduplicate per post ID and ticker. Preserve missing coverage separately from neutral sentiment.
- Shared primary target: next trading session's simple open-to-close return, `next_close / next_open - 1`. Issue forecasts fifteen minutes after the feature session close; text cutoff is that session's close. A separate `next_close` experiment reproduces the old target and is not eligible for the intraday trading simulator.
- Every forecast stores ticker, feature date, issue time, input cutoff, training cutoff, target session/open/close times, actual entry/exit prices when historical, model, feature set, fold, prediction, actual, run ID, target kind, and provenance. No actuals are needed for forward forecast records. A training cutoff is the latest training target close and must precede forecast issue time.
- Chronological walk-forward experiments use train-only transformations and identical held-out dates across ablations. Compare naive, price-only, attention-only, price-plus-attention, price-plus-sentiment, and shuffled-sentiment controls. Compare sentiment against the same model with price-plus-attention to isolate text value beyond post volume. Include linear regression, scaled LinearSVR, and XGBoost when enabled. Correct LSTM sequences/layout and expose an optional LSTM research path. Keep neural forecasts unbounded for regression.
- Persist CSV results and JSON metadata under ignored `artifacts/`. Metadata identifies input hashes, code revision, seed, model/encoder versions, time assumptions, dataset type, feature/target definitions, and covered dates. Synthetic data is clearly labelled at every presentation surface and is not evidence of financial performance.
- Compare return MAE/RMSE/directional accuracy, baseline-relative error, and performance by causal volatility regimes. Use a time-block bootstrap for error-improvement intervals. Include a separate realized-volatility target experiment to examine sentiment disagreement; optional user-provided events allow event/non-event metrics.
- The December 2021 git commit `fc6a3730cdc85021f7c0a0a3756b8c9c06b38eec` contains approximately 892k processed tweet rows plus prices and daily aggregates, despite current `/data/` exclusion. Recover locally from git objects; never re-commit that corpus. Preserve existing sentiment labels by default for fast historical runs. Mark the recovered tweets as a processed non-neutral subset and their time precision as date-only. Real historical results are retrospective under an assumed delay, not strict point-in-time proof.
- Start trading with a transparent long/cash rule chosen before the test run. Enter next open and exit same-session close; apply cost and slippage per side. Report net/gross equity, cash, clearly defined buy-and-hold benchmark, drawdown, turnover, exposure, and cost sensitivity. Do not optimize thresholds against test actuals.
- Forward paper recording must accept only forecasts whose issue time is in the past and whose target open is in the future at the recording clock. No actual prices or labels may enter the recording command. Use append-only SQLite records keyed by forecast identity; identical retries are idempotent and changed retries fail. Settlement uses supplied prices after target close; no overwritten records. Keep history and forward paper performance separate. No broker orders.
- Public X collection is optional, uses X API v2 with the bearer token from `X_BEARER_TOKEN`, bounded start/end times and pagination, no printed credentials; collection is only triggered by an explicit CLI command. FinBERT and tweet-RoBERTa scoring are optional lazy-loaded adapters, with version/corpus-period caveats in metadata and documentation. Default scoring is offline VADER; provided historical scores need no model download.
- Preserve legacy callers where practical; `config.example.py` restores discoverability without secrets. Fix evaluator alignment, chronological splitting, recursive directories, sentiment call/data path errors, and use the same sliding windows at legacy LSTM train/evaluation. Export legacy charts without requiring a browser for mandatory tests.
- Streamlit reads saved run artifacts and has Research, Sentiment, Backtest, Paper, and About views. Show coverage, provenance, source samples, forecast traces, ablations, regimes, net/gross returns and ledger states. Use readable editorial typography, warm light surfaces, restrained teal/amber charts, labelled controls, responsive layouts, downloads, and clear empty/error states. No automatic network fetches on page load.
- Add a separate text-classification benchmark over accessible published finance-related post labels. Compare a majority floor, fixed VADER mapping, train-only TF-IDF/logistic regression, frozen FinBERT and Twitter RoBERTa on identical held-out examples; call dataset labels published labels unless documented expert protocol proves otherwise. Keep classification performance separate from stock-return performance. Offer an annotation-preparation workflow for a later blind, qualified, adjudicated expert set.
- Assess the 2025 FinTweet dataset as a separate stock-movement prediction benchmark: its BUY/HOLD/SELL labels are generated from next-market-open returns, not human sentiment. If its point-in-time text can be verified, compare text-only models on the author's chronological latest test period, withholding all price-derived, future, author and split-leaking inputs. Surface source-quality and label-construction caveats beside every result; if timestamps or text reveal post-outcome information, report the audit finding and exclude predictive claims.
- Support the newer Kaggle “Stock Tweets for Sentiment Analysis and Prediction” files as an optional local corpus for 2021–2022 text/price comparison. They provide substantially newer timestamped company posts and daily OHLCV, but no gold sentiment labels. Treat sentiment outputs as model scores, not truth, and make the large 2015–2020 `Tweet.csv`/`Company_Tweet.csv` corpus import/recovery path explicit.
- Support local import and source-aware analysis of the TimKoornstra 38k finance-text compilation. The source files contain a mixture of dataset constituents and published label schemes; preserve source URL provenance, do not claim all rows are tweets, experts or independently labeled, and do not claim ticker/temporal prediction inputs because those fields are absent. Headline sentiment classification results must use a source-held-out split with normalized duplicate text removed across sources. Train and compare a pinned financial encoder only on non-test sources; report class metrics, confusion, calibration, sample support, and source-specific dataset caveats. Classification scores do not establish stock-return predictiveness.
- Preserve the original source and 65 charts from base commit `4818069c5c22f085aab08d127326a578a79e55d5` under `legacy/original/`. Add aligned old-versus-corrected graphs and the benchmark results to the dashboard, while identifying original train/validation/test plots as historical context because their split/target methodology is flawed.
- Verification: behavioral tests for lookahead, labels, layout, split integrity, cost accounting, temporal recording rules and persistence, plus Streamlit AppTest interactions. Run synthetic demo and recovered real-data experiments; do not claim profitable results. All source changes stay on the dedicated branch.

## Architecture

`sentiment_stock/data.py` handles canonical input and recovery; `sentiment.py` scores posts; `features.py` builds causal rows; `research.py` evaluates models and exports artifacts; `trading.py` backtests; `paper.py` persists forward forecasts; `cli.py` exposes commands. `dashboard.py` reads these artifacts and uses the same backtest functions. A small deterministic demo generator makes all three areas usable without external accounts.
